# CONTRIBUTING GUIDE 🤝

## ЗАГАЛЬНА ІНФОРМАЦІЯ 📌

Цей документ описує правила роботи з проєктом **To-Do List Application** для розробників та користувачів.

Мета — забезпечити єдиний стиль розробки та зручну командну роботу.

---

## 🚀 ЯК ПОЧАТИ РОБОТУ З ПРОЄКТОМ

### 1. Клонуйте репозиторій:

```bash
git clone https://github.com/username/repository.git
```

### 2. Перейдіть у папку проєкту:

```bash
cd repository
```

### 3. Створіть нову гілку для змін:

```bash
git checkout -b feature-name
```

---

## 🛠️ ПРАВИЛА ВНЕСЕННЯ ЗМІН

* Кожна задача або виправлення виконується в окремій гілці
* Назви гілок повинні бути зрозумілими:

  * `fix-bug-name`
  * `feature-add-task`
* Заборонено працювати напряму в `main/master`

---

## 💾 КОМІТИ

Коміти повинні бути зрозумілими:

* Add task validation
* Fix delete task bug
* Update UI layout

---

## 🔄 PULL REQUEST

### 1. Запушити гілку:

```bash
git push origin feature-name
```

### 2. Створити Pull Request на GitHub

### 3. Дочекатися перевірки коду

### 4. Після approval зміни зливаються в `main`

---

## 🧪 ТЕСТУВАННЯ

Перед створенням Pull Request необхідно:

* Перевірити запуск програми
* Перевірити основний функціонал
* Запустити тести (якщо є)

---

## 🚫 ЩО ЗАБОРОНЕНО

* Прямі зміни в `main/master`
* Пуш неперевіреного коду
* Ігнорування стилю коду

---

## 👨‍💻 СТИЛЬ РОБОТИ

* Писати чистий і зрозумілий код
* Дотримуватись структури проєкту
* Робити маленькі логічні коміти

---

## 📌 ПРИМІТКА

Дотримання цих правил допомагає підтримувати якість проєкту та спрощує командну розробку.
